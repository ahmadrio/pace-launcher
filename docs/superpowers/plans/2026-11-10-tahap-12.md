# Tahap 12 (Emoji Skin Tone, Deferred Fixes) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A skin-tone setting for emoji, and the tahap-11 deferred minors.

**Architecture:**
- Core:
  - `Emoji/EmojiSkinTone`, `EmojiCatalog.toned(_:skinTone:)`
  - `SettingsData.emojiSkinTone`
  - quicklink browser trimming
- App:
  - emoji mode ⌘T, toned rows, and paste
  - the Settings picker
  - Log Out arm tied to the notice, with use recorded on run
  - fallback HUD result
  - dry-run order

**Tech Stack:** Swift 6.4, SwiftPM, AppKit/SwiftUI, Swift Testing. Command Line Tools only.

**Spec:** `docs/superpowers/specs/2026-11-10-tahap-12-design.md`.

## Global Constraints
- Same as tahap 11. No new permissions.
- UI checks use the test folders, the focus guards, clipboard snapshots, and `DOTSystemCommandDryRun` for system commands.

## Review Focus
1. **Only modifier bases change.** 👍 → 👍🏽, ☝️ → ☝🏽, while ❤️, 🔥 and 🇮🇩 stay as they are. Test: Task 1 `` `skin tone changes only emoji that take it` ``.
2. **Usage survives a tone change.** Frecency is keyed by the base emoji. Test: Task 2 UI check (empty query after switching tone).
3. **settings.json stays loadable.** An unknown tone value gives Default. Test: Task 1 `` `skin tone loads leniently` ``.
4. **Log Out cannot run from a stale arm.** ↩, type a letter, delete it, ↩ → only the notice. Test: Task 3 UI check (dry run).
5. **Trimmed browsers.** `" com.apple.Safari \n"` → `"com.apple.Safari"`. Test: Task 3.
