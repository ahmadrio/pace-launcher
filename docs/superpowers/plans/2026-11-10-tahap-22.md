# Tahap 22 (Release Package) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sign every build with one self-signed identity, and make `make release` produce a checked 1.0.0 DMG plus checksum; open new script templates in a text editor instead of running them.

**Architecture:**
- **App:** `ScriptLibrary.createTemplate()` opens the file with the default plain-text app, falling back to revealing it in Finder.
- **Scripts:**
  - `scripts/make-signing-identity.sh` creates the identity once.
  - `scripts/build-app.sh` picks the identity: self-signed by default, ad-hoc fallback for debug only.
  - `scripts/package-release.sh` builds, checks, and packages.
- **Docs:** `docs/INSTALL.md`, `docs/RELEASING.md`, HANDOFF.

**Tech Stack:** Swift 6.4, SwiftPM, AppKit, bash, `/usr/bin/openssl` (LibreSSL), `security`, `codesign`, `hdiutil`, `shasum`.

**Spec:** `docs/superpowers/specs/2026-11-10-tahap-22-design.md`.

## Global Constraints
- **No GitHub repo, push, or upload in this stage.**
- **Pace's keychain changes only after his yes at that moment.** Tell him to expect a one-time "codesign wants to use key" prompt.
- **The private key never lands in the repo, the DMG, a log, or the transcript.** Temp files live under `$TMPDIR` with umask 077 and are deleted.
- **The app stays uninstalled on Pace's Mac** (his request). The UI check in Task 1 installs it on test folders, then quits and removes it again without a relaunch.
- **Never send keystrokes to the terminal.** Use the guarded tools.
- **Only close TextEdit documents this stage opened.**
- Identity name: `PACE Launcher Signing`. DMG name: `PACE-Launcher-<version>.dmg`. Version: `1.0.0`.

## Review Focus
1. **The private key stays private.** After creating the identity, `git status` is clean, no `*.p12`/`*.pem`/`*.key` exists in the repo, and the DMG holds only the app. Test: Task 2 and Task 3 checks; `.gitignore` gains those patterns.
2. **Building without Pace's certificate.** `PACE_SIGN_IDENTITY=none-such make app` still builds (ad-hoc, with a warning), while `make release` refuses. Test: Task 2 Step 4 and Task 3 Step 3.
3. **The DMG holds a working, correctly signed app.** The mounted app verifies with `codesign --verify --strict`, its requirement holds the identity's hash, it is arm64, and its version is 1.0.0. The checksum file verifies with `shasum -a 256 -c` from the folder it sits in. Test: Task 3, built into the script.
4. **A dirty tree is never released.** Test: Task 3 Step 3.
5. **Create Script Command never runs the script.** The file opens in the plain-text app, and no terminal opens. Test: Task 1 UI check.
6. **The identity script runs once.** A second run refuses and leaves the keychain unchanged. Test: Task 2 Step 3.

### Task 2: One signing identity

**Files:**
- Create: `scripts/make-signing-identity.sh`
- Modify: `scripts/build-app.sh`, `Makefile` (`signing-identity` target), `.gitignore` (`*.p12`, `*.pem`, `*.key`)

**Interfaces:**
- Produces:
  - `scripts/build-app.sh [debug|release]` reads `PACE_SIGN_IDENTITY`, defaulting to the SHA-1 of "PACE Launcher Signing".
  - If that identity is missing: `debug` signs ad-hoc with a warning on stderr, and `release` exits 1 with "signing identity … not found; see docs/RELEASING.md".
  - With a real identity, it fails unless the designated requirement is certificate based.
  - `make signing-identity` runs `scripts/make-signing-identity.sh`.

- [ ] **Step 1: Write `make-signing-identity.sh`:**
  - Uses `/usr/bin/openssl`: RSA 3072, 7300 days, CN `PACE Launcher Signing`, extensions `basicConstraints=critical,CA:false`, `keyUsage=critical,digitalSignature`, `extendedKeyUsage=critical,codeSigning`.
  - Builds a p12 with a random password and imports it with `security import … -k login.keychain-db -T /usr/bin/codesign`.
  - Deletes the temp dir and prints the SHA-1.
  - Exits 1 with "already exists" if `security find-identity -p codesigning` lists the name.
- [ ] **Step 2: Ask Pace,** then run it once. Expected: one identity "PACE Launcher Signing" listed under matching identities, untrusted is fine.
- [ ] **Step 3: Run it again.** Expected: exit 1 "already exists", and still exactly one such identity.
- [ ] **Step 4: Update `build-app.sh`** with the identity logic and the SHA-1 from Step 2, then verify:
  - `make app`: signed by "PACE Launcher Signing", with a requirement holding `H"<sha1>"`. Accept the prompt if shown.
  - `PACE_SIGN_IDENTITY=0000000000000000000000000000000000000000 scripts/build-app.sh debug`: ad-hoc, with the warning, exit 0.
  - The same with `release`: exit 1 with the message.
  - `make test`: all pass. `git status`: only the intended files.
- [ ] **Step 5: Commit** `Sign every build with one self-signed identity`.

### Task 3: Release package

**Files:**
- Create: `scripts/package-release.sh`, `docs/INSTALL.md`, `docs/RELEASING.md`
- Modify: `Resources/Info.plist` (`CFBundleShortVersionString` 1.0.0), `Makefile` (`release` target)

**Interfaces:**
- Consumes: `scripts/build-app.sh release` from Task 2.
- Produces: `make release` writes `build/release/PACE-Launcher-<version>.dmg` and `.dmg.sha256`, and prints both paths.

- [ ] **Step 1: Write `package-release.sh`.** It follows the spec's steps 1–6, failing with a clear message at each check:
  - The requirement must contain the identity's SHA-1, compared case-insensitively.
  - `lipo -archs` must be `arm64`.
  - The DMG is staged with the app plus an `Applications → /Applications` symlink: `hdiutil create -volname "PACE Launcher" -format UDZO -ov`, then `hdiutil verify`.
  - Mount: `hdiutil attach -readonly -nobrowse -noautoopen -mountpoint <tmp>`, then `codesign --verify --strict`, plus the same version and hash checks on the mounted app. Detach in a trap.
  - The checksum is written from inside `build/release`, so the file names the bare DMG name.
  - Informational only: `spctl -a -t exec -vv` is expected to say rejected.
- [ ] **Step 2: Docs.** Write `INSTALL.md` and `RELEASING.md` to the spec's lists, with the exact commands the script uses.
- [ ] **Step 3: Verify.**
  - With an uncommitted change: `make release` exits 1 "uncommitted changes".
  - `PACE_SIGN_IDENTITY=0000… make release` exits 1.
  - Then commit, and run `make release` on a clean tree. Expected:
    - both files exist
    - `cd build/release && shasum -a 256 -c *.sha256` reports OK
    - the DMG listing shows only `PACE Launcher.app` and `Applications`
    - no key material in the DMG
- [ ] **Step 4: Commit** `Package 1.0.0 as a checked DMG with a checksum`. If Step 3 needed changes, commit them as a follow-up.
