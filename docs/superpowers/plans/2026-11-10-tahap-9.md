## Review Focus
1. **Day boundaries and DST.** "today" starts at local midnight; `23.00 wib in tokyo` is the next day there; `5pm in london` uses the zone's offset on that day. Test: Task 2 `` `converted times can cross midnight` ``.
2. **Plain words show no row**, and existing conversions keep their meaning. `now`, `today`, `time`, `tokyo`, `5 in tokyo`, `10 in in cm` (still a length conversion) and `5 min to s` give no date row. Test: Task 1 `` `plain words are not date queries` `` + Task 3 UI check.
3. **Countdowns without a year pick the right occurrence.** `until` → today or later; `since` → today or earlier; impossible dates (`31 feb`) give no row. Test: Task 1 `` `countdowns pick the next or last occurrence` ``.
4. **Month arithmetic clamps.** `today + 1 month` on 31 Jan gives 28 Feb. Test: Task 1 `` `month steps clamp to the month's end` ``.
5. **Hand-written ids and symlinked folders.** A non-UUID id loads; a script folder reached through `/tmp` or a symlink still matches FSEvents' real paths. Tests: Task 4 and Task 5.

### Task 1: Date arithmetic and countdowns (Core)

**Files:**
- Create: `Sources/DOTLauncherCore/DateMath/DateQuery.swift`
- Test: `Tests/DOTLauncherCoreTests/DateQueryTests.swift`

**Interfaces:**
- Produces:
  ```swift
  public enum DateQuery {
      public enum Result: Equatable, Sendable {
          case date(Date, withTime: Bool)
          case days(Int)                                   // until: ≥ 0 into the future; since: ≥ 0 into the past
          case time(Date, zone: TimeZone, place: String, dayChanged: Bool)
      }
      /// Nil for anything that is not one of the spec's forms.
      public static func evaluate(_ input: String, now: Date, timeZone: TimeZone) -> Result?
      /// (title, copied text). Dates: `.full` date (+ `.short` time when withTime); days: "280 days" / "1 day" /
      /// "Today", copying the number; times: "<short time> <place>" + " · <short weekday>" when dayChanged,
      /// copying the time.
      public static func display(_ result: Result, locale: Locale, timeZone: TimeZone) -> (title: String, copy: String)
  }
  ```
  - Input is lowercased and trimmed, and runs of spaces are collapsed.
  - Arithmetic: `<base>(\s*[+-]\s*\d+\s*<unit>)+`. The Gregorian calendar in `timeZone` is used. Bases and units are as in the spec. Minutes/hours make `withTime` true.
  - Countdown: `days? (until|till|to|since) <date>` and `hari (menuju|sampai|sejak) <date>`. The date may be:
    - a base word
    - `yyyy-mm-dd`
    - `d <month> [yyyy]`
    - `<month> d[,] [yyyy]`

    Months (English + Indonesian, full + 3-letter forms): jan/januari/january, feb/februari/february, mar/maret/march, apr/april, mei/may, jun/juni/june, jul/juli/july, aug/agu/agt/agustus/august, sep/sept/september, oct/okt/oktober/october, nov/november, dec/des/desember/december.

- [ ] **Step 1: Write the failing tests.** `now` = 2026-11-10 14:53 in Asia/Jakarta.
  - `` `dates move by units` ``:
    - `now + 3 days` → 2026-11-13 14:53, withTime
    - `today + 2 weeks` → 2026-11-24 00:00, no time
    - `tomorrow - 1 day` → 2026-11-10 00:00
    - `besok + 1 bulan` → 2026-12-11
    - `today + 1 week + 2 days` → 2026-11-19
    - `today + 3 hours` → 2026-11-10 03:00, withTime
    - `hari ini + 2 hari` → 2026-11-12
    - `Now+90min` → 2026-11-10 16:23
  - `` `month steps clamp to the month's end` ``: with `now` = 2027-01-31 10:00, `today + 1 month` → 2027-02-28.
  - `` `countdowns pick the next or last occurrence` ``:
    - `days until 17 aug` → 280
    - `days until 25 dec` → 45
    - `days since 17 agustus` → 85
    - `hari menuju 2026-12-25` → 45
    - `days until 10 nov` → 0
    - `days until aug 17, 2027` → 280
    - `days since today` → 0
  - `` `plain words are not date queries` ``: nil for `now`, `today`, `time`, `tokyo`, `now + 3`, `today + 3 bananas`, `now plus 3 days`, `days until`, `days until bananas`, `days until 31 feb`, `10 in in cm`, `5 min to s`, `2+2`.
  - `` `results read naturally` `` (en_US, Asia/Jakarta):
    - `.days(280)` → ("280 days", "280"); `.days(1)` → ("1 day", "1"); `.days(0)` → ("Today", "0")
    - the `.date(_, withTime: false)` title for 2026-11-13 contains "November 13, 2026", and its copy equals its title.

### Task 2: Time zones (Core)

**Files:**
- Create: `Sources/DOTLauncherCore/DateMath/TimeZoneNames.swift`
- Modify: `DateQuery.swift`
- Test: `DateQueryTests.swift`

**Interfaces:**
- Produces:
  ```swift
  public enum TimeZoneNames {
      /// "wib" → (Asia/Jakarta, "WIB"); "tokyo" → (Asia/Tokyo, "Tokyo"); "jst" → (Asia/Tokyo, "JST"); nil when unknown.
      public static func zone(for name: String) -> (zone: TimeZone, place: String)?
  }
  ```
  - Order: WIB/WITA/WIT/AEST/UTC/GMT table → `TimeZone(abbreviation:)` (2–5 letters) → city (last identifier component, `_` → space) → aliases (nyc, sf, bali, beijing, mumbai, delhi).
  - The place for a city is title-cased ("New York").
  - DateQuery forms:
    - `time in <zone>` / `jam di <zone>` / `waktu di <zone>`
    - `<time> [<zone>] (in|to|ke) <zone>`, where time is `\d{1,2}([:.]\d{2})?\s*(am|pm)?` with minutes or am/pm required, hours 1–12 with am/pm and 0–23 otherwise.

- [ ] **Step 1: Write the failing tests** (now as in Task 1, local zone Asia/Jakarta):
  - `` `zones by name` ``: `wib`, `WITA`, `wit`, `jst`, `pst`, `aest`, `utc`, `tokyo`, `New York`, `nyc`, `bali` resolve to the expected identifiers; `atlantis` → nil.
  - `` `time in a place` ``: `time in tokyo` → `.time(now, zone: Asia/Tokyo, place: "Tokyo", dayChanged: false)`.
  - `` `converted times can cross midnight` ``:
    - `5pm in london` → the instant 2026-11-10 17:00 WIB, London, same day
    - `9:30am jst to wib` → 2026-11-10 07:30 WIB, place "WIB"
    - `23.00 wib in tokyo` → dayChanged true
    - `17:00 ke new york` → place "New York"
  - `` `ambiguous times are not converted` ``: nil for `5 in tokyo`, `13pm in tokyo`, `25:00 in tokyo`, `time in atlantis`.
  - Display: `.time` for 23.00 WIB → Tokyo (en_US) has a title containing "Tokyo" and " · " and copies only the time.
