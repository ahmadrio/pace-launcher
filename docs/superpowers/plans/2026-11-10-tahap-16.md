# Tahap 16 (Per-Emoji Skin Tone) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A skin tone per emoji that overrides the default, plus the tahap-15 minors.

**Architecture:**
- Core:
  - `EmojiCatalog.canTone`
  - `EmojiSkinTone.cycleOverride`
  - `SettingsData.emojiSkinTones` and `skinTone(for:)`
- App:
  - a ⌘⇧T row action in emoji mode
  - the Settings count and Reset
  - the form comment fix

**Tech Stack:** Swift 6.4, SwiftPM, AppKit/SwiftUI, Swift Testing. Command Line Tools only.

**Spec:** `docs/superpowers/specs/2026-11-10-tahap-16-design.md`.

## Global Constraints
- Same as tahap 15. No new permissions.
- UI checks:
  - Use the test folders, clipboard snapshots, and TextEdit documents you create.
  - Every key goes through a guard that checks DOT's focus (and that the frontmost app is not a terminal) right before that key.
  - No multi-key AppleScripts with delays.

## Review Focus
1. **An override only changes its own emoji.** With 👍 = Medium and default = Default, 👋 stays yellow. Test: Task 1 `` `per-emoji tones override the default` `` + Task 2 UI check.
2. **Emoji that cannot be toned get no action and never change.** ❤️, 👪 and 🇮🇩. Test: Task 1 `` `which emoji can be toned` `` + Task 2 UI check (❤️ row has no ⌘⇧T).
3. **settings.json loads with bad per-emoji data.** An unknown tone is dropped, a non-object gives an empty map, and the other settings survive. Test: Task 1 `` `per-emoji tones load leniently` ``.
4. **Usage stays per base emoji.** After pasting 👍🏽, an empty query lists 👍 (toned) among the first rows. Test: Task 2 UI check.
5. **Reset clears every override.** Settings › General shows the count, and Reset brings it to 0. Test: Task 2 UI check.

### Task 1: Core

**Files:**
- Modify:
  - `Sources/DOTLauncherCore/Emoji/EmojiCatalog.swift`, `EmojiSkinTone.swift`
  - `Sources/DOTLauncherCore/Settings/SettingsData.swift`
- Test: `EmojiCatalogTests.swift`, `SettingsFileTests.swift`

**Interfaces:**
- Produces:
  ```swift
  // EmojiCatalog
  public static func canTone(_ emoji: Emoji) -> Bool        // toned(_:skinTone: .medium) would change it
  // EmojiSkinTone
  public static func cycleOverride(_ current: EmojiSkinTone?) -> EmojiSkinTone?
  // nil → .default → .light → … → .dark → nil
  // SettingsData
  public var emojiSkinTones: [String: EmojiSkinTone] = [:]  // keyed by the catalog's base character
  public func skinTone(for emoji: Emoji) -> EmojiSkinTone   // emojiSkinTones[emoji.character] ?? emojiSkinTone
  ```
- [ ] **Step 1: Write the failing tests:**
  - `` `which emoji can be toned` ``: 👍 and ☝️ are true; ❤️, 👪 and 🇮🇩 are false.
  - `` `per-emoji tones cycle` ``: from nil, eight steps give `.default, .light, .mediumLight, .medium, .mediumDark, .dark, nil, .default`.
  - `` `per-emoji tones override the default` ``:
    - Setup: default `.medium`, with 👍 → `.dark` and 👏 → `.default`.
    - Expected: 👍 → `.dark`, 👋 → `.medium`, 👏 → `.default`.
  - `` `per-emoji tones load leniently` ``:
    - `{"emojiSkinTones": {"👍": "dark", "👋": "purple"}}` → `["👍": .dark]`.
    - `{"emojiSkinTones": 3, "showMenuBarIcon": false}` → `[:]`, and the icon setting is kept.
    - A missing key → `[:]`.
    - The value round-trips.
- [ ] **Step 2: Run** the filters. Expected: failures.
- [ ] **Step 3: Implement.** Decode as `[String: String]` and keep the values that parse.
- [ ] **Step 4: Run** `make test`. Expected: all pass.
- [ ] **Step 5: Commit** `Remember a skin tone per emoji`.

### Task 2: App

**Files:**

- [ ] **Step 1: Implement.**
  - **Rows:** tone with `settings.data.skinTone(for: found)`.
  - **Row action for toneable emoji:** "Skin Tone for This Emoji", `.command("t", shift: true)`, `.stay`.
    - It cycles `settings.data.emojiSkinTones[found.character]` with `cycleOverride`; nil removes the key.
    - With a value, the notice reads "<toned emoji> skin tone: <title> <modifier>".
    - With nil, it reads "<base> follows the default skin tone (<default title>)".
  - **Settings › General › Emoji:**
    - A caption "N emoji have their own skin tone" (or "1 emoji has its own skin tone") when N > 0.
    - A "Reset" button (`accessibilityIdentifier("reset-emoji-tones")`) that sets `[:]`.
  - **Comment:** `onFocused` "runs after focus is requested; moves typed-ahead text once the field has the keyboard".
- [ ] **Step 2: Run** `make test`. Expected: all pass.
- [ ] **Step 3: UI check** (test folders; clipboard snapshot; a new TextEdit document):
  - **Toned row:**
    1. Emoji `thumbs` → ⌘⇧T ×5 → notice "👍🏽 skin tone: Medium 🏽" (after nil → default → light → mediumLight → medium).

  - **Usage:** reopen with an empty query → 👍🏽 among the first rows.

  - **Cleanup:** remove the temporary files, close the document, restore the clipboard if needed, and put the app back on real data.
