# Tahap 20 (Small Leftovers) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Persist failed system-command logs and give clear "already running" HUDs.
- Make password-first script forms run on one ↩.
- Focus the first typing field when a form starts with a dropdown.

**Architecture:**
- **Core:**
  - `SystemCommand.busyMessage`
  - `ScriptArgument.firstTypingIndex(in:)`
- **App:**
  - runner log level
  - AppDelegate HUD
  - ScriptArgumentsView: `.textContentType(.oneTimeCode)` on SecureField, and focus on the first typing field

**Tech Stack:** Swift 6.4, SwiftPM, AppKit/SwiftUI, Swift Testing. Command Line Tools only.

**Spec:** `docs/superpowers/specs/2026-11-10-tahap-20-design.md`.

## Global Constraints
- Same as tahap 19. No new permissions.
- UI checks:
  - Run on the test folders.
  - Send keys only through the guarded tools (`guardtype`, `launcherkeys.sh`).
  - Never run Restart, Shut Down or Empty Trash for real.

## Review Focus
1. **No password text reaches a log.** The finished line holds only the command id and the osascript ending, and script runs are untouched. Test: code reading + Task 2 log check.
2. **A password-first form runs on one ↩ with typed-ahead text.** Test: Task 2 UI check (RED was seen before the change: the "Passwords…" popup).
3. **A dropdown-first form focuses its text field, and typed-ahead text lands there.** Test: Task 2 UI check.
4. **A dropdown-only form is unchanged.** No focus is forced, and the text stays in search. Test: Task 1 `` `first typing field` `` (nil).
5. **Busy messages per command.** Test: Task 1.
