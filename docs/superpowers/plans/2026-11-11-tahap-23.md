# Tahap 23 (Welcome, Permissions, Update Check) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show new users a one-time welcome window with live permission status, and tell them about new GitHub releases (once a day, can be turned off, never installs anything).

**Architecture:**
- **Core (tested):** `Updates/` reads versions and GitHub's answer and decides what to show. `Welcome/PermissionChecklist` turns raw permission facts into rows. `Support/MachineDefaults` keeps test runs away from Pace's real first-run flags.
- **App:** `Updates/UpdateChecker` (network, schedule, HUD, dialog), `Welcome/` (window, view, live status model), plus menu bar, launcher command, and Settings wiring.

**Tech Stack:** Swift 6.4, SwiftPM, AppKit + SwiftUI, URLSession, Swift Testing.

**Spec:** `docs/superpowers/specs/2026-11-11-tahap-23-design.md`.

## Global Constraints
- UI text is English. Docs for users are English; HANDOFF is Indonesian.
- Repo constant: `ahmadrio/pace-launcher`. API: `https://api.github.com/repos/ahmadrio/pace-launcher/releases/latest`. Headers: `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`, `User-Agent: PACELauncher`. Ephemeral session, no cookies, no URL cache, 10 s timeout.
- Check interval: 24 h after the last successful answer (200 or 404); retried hourly; first try 10 s after launch.
- `settings.json` key `checkForUpdates`, default `true`. UserDefaults keys `welcomeShown`, `lastUpdateCheck`, `announcedUpdateVersion`, each with the suffix `.testData` while test folders are in use. Test hook: `PACEUpdatesURLOverride`.
- No automatic check while the welcome window is open, while `checkForUpdates` is off, or while test folders are in use without `PACEUpdatesURLOverride`.
- Never open a URL that came from the network. Never open a real website in tests (do not click Download).
- Tests never touch real data or real iCloud (`t6/env.sh on`). The app stays uninstalled on Pace's Mac after this stage: quit it, delete `~/Applications/PACE Launcher.app`, and do not relaunch it on real data.
- Never send keystrokes to a terminal; UI checks click through AX and type only with `t12/guardtype`. Close windows through their AX close button, never with an unguarded Esc.
- No GitHub repo, push, or release in this stage.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus
1. **GitHub unreachable, rate-limited, or answering garbage.** Expected: no crash, no HUD, an automatic retry at most once an hour, and a manual check that names the reason. Test: Task 1 `outcome maps every status`; Task 3 UI check with the server stopped.
2. **An answer that tries to steer PACE** (a tag like `v1.2.3/../x`, an `html_url` elsewhere). Expected: never opened; the page URL is built from the repo constant and a tag that parsed as a version. Test: Task 1 `release page comes from the repo, not the answer`.
3. **Updates switched off.** Expected: zero requests, including after the welcome window closes and on the hourly tick. Test: Task 3 and Task 4 UI checks read the local server's request log.
4. **The same release seen again after a relaunch.** Expected: the HUD appears once per version; the menu item stays. Test: Task 1 `announces each version once`; Task 3 relaunch check.
5. **Test runs and Pace's first launch from GitHub.** Expected: UI checks never set `welcomeShown`, `lastUpdateCheck` or `announcedUpdateVersion` without the `.testData` suffix. Test: Task 2 `test folders get their own keys`; Task 4 `defaults read` check.

**Interfaces:**

  - `public struct GitHubRelease: Sendable, Equatable { tag: String; version: AppVersion; isDraft: Bool; isPrerelease: Bool; static func decode(_ data: Data) -> GitHubRelease? }`
  - `public enum UpdateCheck` with `repository`, `latestReleaseAPI: URL`, `interval: TimeInterval = 86_400`, `enum Outcome: Equatable, Sendable { case available(GitHubRelease), upToDate, noRelease, failed(String) }`, `outcome(current: AppVersion, status: Int, body: Data) -> Outcome`, `isDue(lastSuccess: Date?, now: Date) -> Bool`, `releasePage(for: GitHubRelease) -> URL`, `shouldAnnounce(_: GitHubRelease, announced: String?) -> Bool`
  - `SettingsData.checkForUpdates: Bool` (default `true`)

- [ ] **Step 1: Write the failing tests** in `UpdateCheckTests.swift`:
  - `reads versions`: `"1.2.3"`, `"v1.2.3"`, `"V1.2"` (→ 1.2.0), `"2"` (→ 2.0.0) parse; `""`, `"v"`, `"1.2.3.4"`, `"1.2.3-beta"`, `"1..2"`, `" 1.2"`, `"+1"`, `"1.-2"`, `"v1.2.3/../x"` are nil; `description` of `"v1.2"` is `"1.2.0"`.
  - `compares versions`: 1.0.0 < 1.0.1 < 1.1.0 < 2.0.0; 1.10.0 > 1.9.0; `"1.0"` == `"1.0.0"`.
  - `decodes a release`: `{"tag_name":"v1.1.0","draft":false,"prerelease":false,"html_url":"https://evil.example"}` → tag `v1.1.0`, version 1.1.0; missing `draft`/`prerelease` → false; unparseable tag, non-JSON, and `[]` → nil.
  - `outcome maps every status` (current 1.0.0): 200 newer → `.available`; 200 same → `.upToDate`; 200 older → `.upToDate`; 200 newer prerelease or draft → `.upToDate`; 200 garbage → `.failed("GitHub sent an answer PACE can’t read.")`; 404 → `.noRelease`; 403 and 429 → `.failed("GitHub is limiting requests. Try again later.")`; 500 → `.failed("GitHub answered with status 500.")`.
  - `is due once a day`: nil → true; 23 h ago → false; 24 h ago → true; 2 min in the future → true; 30 s in the future → false.
  - `release page comes from the repo, not the answer`: tag `v1.1.0` → `https://github.com/ahmadrio/pace-launcher/releases/tag/v1.1.0`, whatever `html_url` said; `latestReleaseAPI.absoluteString == "https://api.github.com/repos/ahmadrio/pace-launcher/releases/latest"`.
  - `announces each version once`: announced nil → true; announced `"1.1.0"` and release 1.1.0 (tag `v1.1`) → false; announced `"1.1.0"` and release 1.2.0 → true.
- And in `SettingsFileTests.swift`: `check for updates defaults to on and round-trips` (file without the key → `true`; save `false` → loads `false`).

### Task 3: Update checker in the app

**Files:**
- Create: `Sources/PACELauncher/Updates/UpdateChecker.swift`, `Sources/PACELauncher/Updates/UpdateAlert.swift`
- Modify: `Sources/PACELauncher/App/AppDelegate.swift`, `Sources/PACELauncher/App/StatusMenuController.swift`, `Sources/PACELauncher/Commands/CommandCatalog.swift`, `Sources/PACELauncher/Settings/SettingsView.swift`, `Sources/PACELauncher/Settings/SettingsWindowController.swift`

**Interfaces:**
- Consumes: Task 1 (`AppVersion`, `GitHubRelease`, `UpdateCheck`, `checkForUpdates`), Task 2 (`MachineDefaults`).
- Produces (`@Observable final class UpdateChecker`):
  - `init(settings: SettingsStore)`; `private(set) var available: GitHubRelease?`, `lastSuccess: Date?`, `isChecking: Bool`; `let current: AppVersion?` (from `CFBundleShortVersionString`)
  - `var isPaused: () -> Bool` (set by Task 4: welcome window open), `var onAnnounce: (GitHubRelease) -> Void`
  - `func start()`, `func checkIfDue()`, `func checkNow()`, `func openDownloadPage()`

- [ ] **Step 1: UpdateChecker.** Behaviour:
  - URL: `PACEUpdatesURLOverride` if set, else `UpdateCheck.latestReleaseAPI`. Session as Global Constraints.
  - `start()`: one `Task` that sleeps 10 s, calls `checkIfDue()`, then loops hourly.
  - `checkIfDue()`: returns unless `settings.data.checkForUpdates`, `!isPaused()`, test-folder rule passes, `current != nil`, `!isChecking`, and `UpdateCheck.isDue`. Logs why it skipped at `.debug`.
  - A check maps the answer with `UpdateCheck.outcome`; network errors become `.failed(error.localizedDescription)`. On `.available`, `.upToDate`, `.noRelease`: store `lastUpdateCheck` (scoped key) and `lastSuccess`; set `available` (nil unless `.available`). On `.available` from an automatic check with `shouldAnnounce`: call `onAnnounce`, store `announcedUpdateVersion` (scoped key). Log outcomes at `.notice` (versions only).
  - `checkNow()`: if a check is running, remember to show the dialog when it ends; otherwise check, then `UpdateAlert.show`.
  - `openDownloadPage()`: opens `UpdateCheck.releasePage(for: available)`.
- [ ] **Step 2: UpdateAlert.** `static func show(_ outcome: UpdateCheck.Outcome, current: AppVersion, download: (GitHubRelease) -> Void)`: `NSApp.activate()`, `NSAlert` with the spec's titles: available → message "PACE Launcher <v> is available", info "You have <current>. Download opens the release page in your browser; install it like the first time.", buttons Download / Later; up to date → "PACE Launcher <current> is up to date."; no release → "No release is published on GitHub yet."; failed → "Couldn’t check for updates" + reason. After the alert, `NSApp.deactivate()` unless a PACE window is key-visible (Settings/Welcome).
- [ ] **Step 3: Wiring.**
  - AppDelegate creates the checker after the HUD and settings; `onAnnounce` → `hud.show("PACE Launcher <v> is available. Download it from the menu bar or with “Check for Updates”.", isError: false, duration: 6)`; `settings.onChange` → `checkIfDue()` when `checkForUpdates` turns on; `start()`.
  - StatusMenuController gets `updates: UpdateChecker`: when `available`, first item "Download PACE Launcher <v>…" → `openDownloadPage()`; "Check for Updates…" above "Settings…".
  - CommandCatalog: `checkForUpdates` command, id `check-for-updates`, aliases `update`, `updates`, `pembaruan`, `version`, `versi`, symbol `arrow.down.circle`, subtitle "Version <current> · <v> is available" / "Version <current> · checked <relative>" / "Version <current>"; action: `.run` → `openDownloadPage()` when available, else `checkNow()`.
  - Settings › General › "Updates": toggle "Check for updates automatically", caption "Once a day PACE asks GitHub for the latest release. Nothing about you or your data is sent, and nothing is installed by itself.", "Version <current> · Last checked <date>" (or "Not checked yet"), "Check Now" (`accessibilityIdentifier("check-updates-now")`), and when available a row "PACE Launcher <v> is available" + "Download…".
- [ ] **Step 4: Build and run the suite.** `make test 2>&1 | tail -3` → all pass; `make app` → builds without warnings from the new files.
- [ ] **Step 5: UI check on test folders** with a local server (`python3 -m http.server 8765 --bind 127.0.0.1` in `scratchpad/t23/server`, request log to a file) and `PACEUpdatesURLOverride=http://127.0.0.1:8765/latest.json`:
